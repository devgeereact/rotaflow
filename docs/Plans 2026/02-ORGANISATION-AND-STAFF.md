# 02. Organisation workspace, staff and mobile

Keep one organisation workspace at `/app`, with the existing Management and My work modes. Do not build a separate staff app. The work below is focused repair and polish of screens that already exist.

## 1. The two loops the product must get right

**Operating week.** Owner signs up → creates the organisation → adds a site and departments → invites managers and staff → staff accept → staff set availability → manager drafts the rota → resolves warnings → publishes → staff see the published week → staff clock in and out → manager corrects exceptions → approves timesheets → exports the period.

**Requests.** Leave, swaps, open shifts and overtime. Each one needs a visible pending state, one authorised decision, a durable result, and a notification that reaches the person.

A pilot organisation must complete both loops for a full week before any sales push ([08](08-DELIVERY-AND-GOVERNANCE.md), phase 2).

## 4. Settings that save but do nothing (VERIFIED)

A manager who changes one of these sees "Changes saved" and nothing else changes. That breaks trust faster than a missing feature. Each one gets wired up or removed. No third option.

| Setting                       | Current state                                                                               | Recommendation                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Minimum rest hours            | Read only by Swaps. The rota uses a hard-coded `MIN_REST_HOURS = 11` (`rotaInsights.ts:37`) | **Wire** into the rota warnings                                                       |
| Maximum weekly hours          | Read only by Swaps. The rota uses `STATUTORY_WEEKLY_MINUTES = 48*60` (`RotaGridRow.tsx:47`) | **Wire** into the rota. Keep 48 as the default and explain the opt-out in plain words |
| Overtime threshold hours      | No consumer outside settings                                                                | **Wire** into Overtime and Timesheets (hours above threshold highlighted)             |
| Maximum consecutive days      | No consumer                                                                                 | **Wire** into the rota warnings (one more check beside rest and weekly hours)         |
| Rounding minutes              | No consumer                                                                                 | **Remove** for now. Rounding changes pay, so it needs its own careful feature         |
| Publish lead days             | No consumer                                                                                 | **Remove** for now. Bring it back as a soft warning only if pilots ask                |
| Auto-decline clashing leave   | No consumer                                                                                 | **Remove**. Managers should decide                                                    |
| Working week (`working_week`) | Written by onboarding and settings, read nowhere (BUG-011)                                  | **Merge** with week-start day. One setting: "Weeks start on". Remove the other        |
| Date format                   | No reader. The app always uses UK formats                                                   | **Remove**. The product is UK-first                                                   |
| Currency                      | No reader. Money is GBP throughout                                                          | **Remove** until a non-UK customer exists                                             |

Acceptance: a test per wired setting proves that changing it changes the warning. The removed settings disappear from the UI, and their stored values stay untouched in `orgPreferences` so nothing is lost.

## 8. Mobile and usability acceptance

Test every journey above at 320, 390, 768, 1024 and 1440 pixels wide, then on one real iPhone and one real Android phone. Include portrait and landscape, browser and installed app, 200% text, the keyboard open, GPS denied, push denied, and a slow or absent connection.

- No sideways page scroll on ordinary screens. Dense grids scroll inside a labelled `ScrollRegion`.
- The bottom tab bar, cookie notice and offline banner never cover a submit or clock-in button.
- Every tap target is at least 44 by 44 pixels. Known offenders: `NotificationBell.tsx:46` at 34 pixels, and about 50 controls sized `h-6` to `h-9` (INFERRED from class names).
- Errors stay visible above the phone keyboard.

Observe at least one owner, one manager and one staff member who have never seen the product. Pilot targets: staff find their next shift without help; staff submit a leave request without help; a manager can explain what Publish changes and whether staff were told. Record time, mistakes and questions. These are acceptance observations, not marketing claims.
